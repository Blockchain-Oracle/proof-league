# Digest: proof-pipeline (round 1)

**Summary:** Claim (a) is verified verbatim: the gluwa/usc-testnet-bridge-examples hello-bridge README states that on a slow source chain like Ethereum or Sepolia, transactions in very recent blocks take ~8-10 minutes to be attested, a delay held necessary against source-chain reversion. Claim (b) is verified via Creditcoin's own Dec 2025 announcement — "Verification will now take only one block (15 seconds) instead of the previous 6-20 minutes with STARK proofs" — but with a correction: verification runs synchronously inside the calling Creditcoin transaction via the Block Prover Precompile at 0x0FD2, so the 15 s is inclusion time, not a separate verification phase. Claim (d) is verified almost word-for-word: the precompile "does not validate if a transaction was successful or not. It only validates if a transaction is included in a block," and the dApp contract must itself check receipt status, expected address and expected event — though it is two proofs (Merkle inclusion plus continuity to an attestation), not one. Claim (c) is mostly verified — the proven payload is "transaction + receipt data" decodable into "type, common fields, type-specific fields and the receipt fields", and the reference bridge extracts from/to/value from an event — but gasUsed is nowhere documented, and the docs' "from" is event-level, not transaction sender, which the claim conflates. Claim (e) splits: the no-absence-proof half is unverifiable from any primary source read, and the no-aggregation half is REFUTED, since the SDK documents batch proving with MAX_BATCH_SIZE of 10 proofs over a MAX_BATCH_RANGE of 1000 blocks. Net latency on the native-verifier path is roughly 9-12 minutes from Ethereum event to Creditcoin settlement, but a sibling official repo (gluwa/ccnext-testnet-bridge-examples) still advertises ~16-30 minute proving, so which stack the deployed testnet runs is a live unresolved risk.

- Measure uncached proof-build time empirically by running the hello-bridge example against Sepolia — the READMEs give attestation wait and total proving time but never isolate proof generation itself.
