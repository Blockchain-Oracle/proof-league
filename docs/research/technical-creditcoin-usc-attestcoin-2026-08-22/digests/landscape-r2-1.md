# Digest: landscape (round 2)

**Summary:** All five round-1 leads were chased and all five open gaps closed with primary sources. The headline finding is that `chainKey` is a Creditcoin-internal source-chain identifier explicitly documented as NOT the EVM chainId: on CC3 Testnet, Ethereum Sepolia = 1 and Ethereum Mainnet = 3; on CC3 Mainnet, Ethereum Mainnet = 1. Sepolia is confirmed still supported from CC3 Testnet, and CC3 Testnet can additionally read real Ethereum Mainnet at chainKey 3 — letting a team prove genuine mainnet transactions while paying testnet gas. Deployed addresses are settled: BlockProver `0x…0FD2` and ChainInfo `0x…0fd3` are identical on both networks, while the Decoder contract differs (mainnet `0x9D094C9f…`, testnet `0x731c345d…`). The chain spec is now primary-sourced rather than inferred: 15s block time, 1–3 block finality, 75M block gas limit, and support for EIP-4337/1271/712. Critically, writability (Creditcoin→Ethereum outbound messaging) is NOT shipped anywhere — docs state it is still in third-party testing and audit and has not even reached testnet — so only inbound readability is buildable today; USC readability has been live on mainnet since ~2026-06-18. The SDK `@gluwa/usc-sdk` is npm-published at 0.18.0 (MIT, 2026-06-22) but its source repo is ~2 months ahead of the last publish.

## Contradictions
- gluwa/USC-Builder-Examples deploys with `--chainkey 102033` against network `cc3_usc_testnet`, which is inconsistent with the documented chainKey scheme (Sepolia=1, Ethereum Mainnet=3 on CC3 Testnet). 102033 resembles an EVM chainId for the legacy USC testnet rather than a source chainKey. Unresolved — treat the repo as targeting the legacy network and re-derive chainKey at runtime via getSupportedChains().
- networks.json assigns Sepolia chainKey 3 on cc3-devnet/usc-devnet but chainKey 1 on usc-testnet, while the docs assign Sepolia chainKey 1 and Ethereum Mainnet chainKey 3 on cc3-testnet. These are different networks so not strictly contradictory, but the overlapping 1/3 values are easy to confuse. The docs Environments page is authoritative for cc3-testnet/cc3-mainnet; networks.json covers only devnets and the legacy usc-testnet and predates the June 2026 mainnet USC launch.
- npm @gluwa/usc-sdk latest is 0.18.0 (2026-06-22) while the source repo HEAD is 2026-08-20 — roughly two months of unpublished commits. Documented SDK examples may not run against the published package.

## Leads
- Fetch https://docs.creditcoin.org/attestcoin-protocol/attestcoin-protocol-operator-guides/per-chain-attestor-settings — the docs reference this 'per-chain settings' table repeatedly as the canonical live chainKey source; it may list chains not in the Environments page.
- Read the four tutorial READMEs inside gluwa/usc-testnet-bridge-examples (hello-bridge, custom-contracts-bridging, bridge-offchain-worker, loan-flow) via `gh api repos/gluwa/usc-testnet-bridge-examples/contents/<dir>/README.md` — these hold the concrete pre-deployed Sepolia + Creditcoin Testnet contract addresses and the exact command sequence, which would de-risk the build path and reveal real attestation wait times.
- Read gluwa/cc-next-query-builder/examples/end-to-end.ts and examples/supported-chains-attestation-information.ts to get the actual runnable API against v0.18.0, and diff repo HEAD against the npm 0.18.0 tarball to determine which documented APIs are unpublished.
- Query the live ChainInfo precompile at 0x…0fd3 on https://rpc.cc3-testnet.creditcoin.network via eth_call to empirically confirm the current supported chains and chainKeys, rather than trusting the docs table — this is the single highest-confidence verification available and costs one RPC call.
- Fetch the testnet Proof Builder swagger at https://proof-gen-api.cc3-testnet.creditcoin.network/ to enumerate the REST surface, rate limits and auth requirements for the off-chain proof fetch step.
- Check gluwa/creditcoin3 releases/changelog for any post-3.131.0 release mentioning writability reaching testnet, and search Creditcoin's official blog or X account for a writability launch announcement to date the capability.

## Not Found
- No documented non-Ethereum source chain on CC3 Testnet or CC3 Mainnet. BSC testnet exists only on the deprecated usc-devnet (chainKey 8). No evidence found of Base, Arbitrum, Polygon, Solana or Bitcoin as source chains.
- No release date or roadmap commitment for writability reaching testnet — docs say only 'undergoing 3rd party testing and audits' with no timeline.
- The exact meaning of `--chainkey 102033` in USC-Builder-Examples was not resolved against the documented 1/3 chainKey scheme.
- `chainEncoding` field (value 1 for Ethereum Sepolia in getSupportedChains output) is returned by the SDK but its semantics and enumerated values were not documented in the corpus read.
- Gas cost of a verify()/verifyAndEmit() call — no benchmark or gas figure found for the BlockProver precompile, only the 75M block gas limit and 0.5 gwei base price.
- Attestation latency in practice — docs say attestation is 'periodic and automatic' and the SDK defaults to a 15m timeout, but no measured or documented typical wait time between source-block finality and attestation availability was found.
- Whether a mainnet swagger/OpenAPI spec exists for the Proof Builder API — docs explicitly redirect to the testnet version.
- Rate limits, authentication requirements or SLA for the hosted prover endpoints (prover.cc3-testnet / proofbuilder.cc3-mainnet-usc).
